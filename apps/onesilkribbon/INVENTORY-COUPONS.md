# 第二批：库存预留、退款与优惠券

仅用于丝带站 Supabase（jmwautbooalixgvlfhnk），不得在玻璃站 Lumina 执行。

## 上线

1. 已执行第一批 payment-reliability 数据库迁移。
2. 执行 `supabase/migrations/2026-10-14-inventory-coupons.sql`，然后立即部署本批代码。
3. Stripe webhook 的事件订阅中加入 `checkout.session.expired`，保留原有付款成功事件。
4. 在测试支付环境确认下单、过期、取消、付款及退款完整流程。

## 库存语义

`product_skus.stock_qty` 现在是可售库存：进入付款流程时扣除预留，付款确认不再重复扣减。
预留记录另外保留，未付款订单通过后台订单页的“取消订单”释放。
Stripe 付款页 30 分钟后过期，收到并验证过期事件后释放；没订阅此事件时需后台取消
（先核对/关闭 Stripe 付款链接，不能只按时间释放）。
PayPal 新订单两小时未开始收款后不再允许发起收款，后续结账会顺带回收这些预留。
这一回收依赖后续结账访问，不是精确定时任务；无访问时可后台手动取消。
一旦已开始 PayPal 收款或已留有付款凭证，就不按时间自动释放，应先核对付款。
旧代码建立的预留不自动套用 PayPal 超时回收，防止历史收款状态不明时误回库。
支付链接创建失败时可能留下安全预留，可在后台取消对应待付款订单释放。

## 并发与恢复

- 同 SKU 购物车行合并，数量严格校验。商品归属、名称及价格读取数据库。
- 订单创建和预留在同一事务，库存不足则全部回滚，不生成付款链接。
- 优惠券行加锁，已用次数加有效预留不能超过限额；取消释放预留，成功付款消耗一次。
- 已开始的退款记录固定退款方式与回库选项；自动退款使用 Stripe 幂等键和退款记录恢复。
- 只有平台确认成功（或管理员明确已手动退款）才改变订单状态；退款状态和回库同一事务。
- 相同验证 token 在同一事务领取同一张欢迎券，邮件失败保留领取结果以便同链接重试。
- 客户表按线上实际结构写入，修正旧订阅验证代码引用不存在的 customers.source 字段。
- 不删除历史订单、会话、库存或优惠券数据，不尝试自动还原历史超卖。
