# 丝带站订单与账户检查（2026-10-24）

范围：本仓库的丝带应用及其使用的 packages/core。玻璃站独立仓库未改；未执行生产数据库写入、发货、扣款、退款或发信。

## 确认并修复

- 发货接口原先忽略订单保存错误，保存失败仍可能记录发货轨迹并通知顾客。现只有订单确实保存成功后才进行这些步骤，查询异常与订单不存在分开处理。
- 发货、修改快递与确认送达增加条件更新：已读状态发生变化则返回冲突，避免把刚退款的订单覆盖成已发货或已送达；发货另比较原有快递信息，避免覆盖同时发生的编辑。
- 修改快递信息保留原始 shipped_at；新的轨迹仍使用实际操作时间。发货参数及追踪链接在服务端校验，拒绝空单号及非 HTTPS、带凭据的网址。
- 物流历史保存失败时，后台明确提示“状态已保存、历史未保存”；不再将部分成功误报成全部失败而鼓励重复操作。邮件失败单独提示；批量发货同样显示历史失败。
- 后台订单详情、装箱单、商品摘要和页签数量查询失败不再伪装成空商品或零订单；邮件日志仍保留既有的可选降级行为。
- 顾客订单详情原先 select('*') 会把后台内部备注与支付平台编号带给浏览器。现用明确的顾客字段列表，保留 user_id 归属筛选；成功响应禁止缓存。商品、轨迹读取失败返回错误，不返回残缺成功数据。
- 顾客订单页区分读取失败与真正的 404，提供重试，并在离开或切换订单时取消旧请求，避免迟到响应覆盖页面。
- 登录回调补建档案改为冲突时忽略插入再读取已有档案，避免旧登录姓名覆盖顾客自己修改的姓名、电话等资料；并发登录也保留现有记录。

## 验证

- 全部 153 项自动测试通过，其中本轮新增 16 项，覆盖数据库读写失败、发货并发冲突、送达与退款冲突、原始发货时间、通知失败、订单隐私、档案保留及页面取消。
- 生产构建与本地生产版本 31 项只读 HTTP 检查通过，包含公开页面、网站地图、商品图片以及未登录时的后台/账户接口拒绝访问。Lint 无错误，保留既有 3 条动态图片建议及框架中间件弃用提示。
- 所有写入和通知场景均使用模拟数据；未用真实顾客订单验证发货或通知。
- 本轮未增加依赖、数据库表、函数或迁移文件。默认地址切换、商品/SKU 保存的原子事务问题仍按前一日记录保留。
- 发货状态与轨迹仍是两次写入，邮件也没有新增持久重试队列；本轮明确反馈部分失败，不宣称整个流程已经是一个事务，也不保证网络中断后的通知恰好发送一次。

## 后续检查：商品、库存与后台读取

- 商品保存不再把“此次列表没有包含”的 SKU 自动当作删除；仅处理 deletedSkuIds 明确指定的记录。旧编辑器无法再删除其他操作员后来新增的规格，已有订单引用的规格仍按原规则停用保留。
- 库存专用接口强制带上加载时的库存并进行条件更新；商品编辑也拒绝没有库存基准的旧客户端，要求刷新后保存，避免无保护覆盖或静默忽略修改。原库存为 null 时使用 SQL null 比较；历史负库存允许作为比较基准修正，但新库存不能为负。
- 商品规格及库存批次在首次数据库写入前检查数值、重复 ID 和删除/保存冲突。空值、布尔值、小数、超出数据库整数范围的库存不再被当成零或截断；价格不再把无效字符串当成零。库存页面也使用同一解析规则。
- 商品编辑器按商品 ID 重建，切换商品时取消旧读取并拒绝不匹配的响应；保存后重载失败不再重置编辑器为过时快照。
- 后台设置读取失败不再返回成功的空设置，也不会把错误伪装成默认运费。设置页提供重新加载，逐字段补默认值，保留合法的零门槛和免运费开关。
- 后台汇总的商品、库存和明细读取异常不再生成貌似完整的统计；通用分页达到安全上限时返回不完整错误，不再成功返回截断数据。可选邮件日志的既有降级行为保留。
- 全部 167 项测试通过，本批新增 14 项；另对修改的 packages/core 后台文件运行 ESLint，0 错误，保留 1 条既有商品缩略图建议。
- 最终生产构建及本地 31 项只读检查通过；真实商品保存、库存编辑及设置写入均未在生产环境执行，相关回归使用模拟数据验证。
- 本批没有新依赖、数据库迁移或真实业务写入。商品/SKU 整体保存与默认地址切换仍不是数据库原子事务；本批只增加已确认的覆盖、误删与读取错误保护，不承诺所有写入全成全败。
